# 프론트+백엔드 통합 주간 회의록 (계획, 미착수)

> 상태: 설계 중 — 아직 코드 작업 시작 안 함. 아래 미정 사항 정리되면 착수.

## 왜 필요한가

지금은 프론트엔드 팀 전용 주간 회의록만 자동 생성됨 (`weekly_report.py`, 이 저장소).

백엔드 팀이 프론트 관련 공유사항을 확인하려고 프론트엔드 회의록 전체를 읽는 건 리소스 낭비라고 판단. 대신 양 팀이 같이 보는 **통합 회의록**을 따로 만들고, 거기서 필요한 내용만 모아서 보는 방향으로 감.

이 논의 과정에서 프론트엔드 회의록에 "4. 백엔드 미팅 공유 사안" 섹션을 추가함(이미 반영됨) — 프론트팀이 백엔드가 알아야 할 내용을 여기 적어두면, 그 내용이 통합 회의록으로 옮겨지는 소스가 됨.

## 확정된 흐름

1. 통합 회의 요일/시간에 맞춰 **별도 GitHub Actions 크론**이 실행됨 (프론트 전용 크론과 별개)
2. 그 시점 기준 **그 주 월요일에 생성된 프론트엔드 회의록 페이지**를 찾음 (이번 주 프론트 회의록 = 소스)
3. 그 페이지에서 **"4. 백엔드 미팅 공유 사안" 섹션 내용만 파싱해서 추출**
4. (예정) 같은 방식으로 **백엔드 회의록의 "프론트 미팅 공유 사항" 섹션**도 파싱해서 추출 — [backend-report-plan.md](./backend-report-plan.md)에서 그쪽 자동화가 먼저 준비돼야 함
5. 통합 회의록 페이지(신규 생성/갱신)에 양쪽 내용을 기입 → **양방향 구조로 방향 잡힘** (프론트→백엔드, 백엔드→프론트 둘 다)

## 아직 미정 — 착수 전 확인 필요

| 항목 | 상태 |
|---|---|
| 통합 회의 요일/시간 (크론 값) | 미정 |
| 통합 회의록 템플릿 구조 | 미정, 직접 설계 예정 |
| 통합 회의록이 들어갈 스페이스/폴더 | 미정 |
| 백엔드 쪽 데이터 반영 방식 | **양방향으로 방향은 잡힘** (백엔드 회의록에도 "프론트 미팅 공유 사항" 섹션 예정). 다만 백엔드 자동화 자체가 아직 없어서, [backend-report-plan.md](./backend-report-plan.md) 진행 상황에 의존 |

## 참고

- 프론트 회의록 소스 코드/구조는 `../README.md`, `../weekly_report.py` 참고
- [backend-report-plan.md](./backend-report-plan.md) — 백엔드 주간 회의록 자동화 계획. 그게 정리되면 여기 "백엔드 쪽 데이터 반영 방식" 항목도 같이 풀릴 수 있음
