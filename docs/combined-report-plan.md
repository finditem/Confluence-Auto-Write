# 프론트+백엔드 통합 주간 회의록 (개발 미팅)

> 상태: 설계·구현·워크플로 완료 (양방향 파싱 포함). 실행 검증만 남음.

## 왜 필요한가

지금은 프론트엔드 팀 전용 주간 회의록만 자동 생성됨 (`frontend/weekly_report.py`, 이 저장소).

백엔드 팀이 프론트 관련 공유사항을 확인하려고 프론트엔드 회의록 전체를 읽는 건 리소스 낭비라고 판단. 대신 양 팀이 같이 보는 **통합 회의록(개발 미팅)**을 따로 만들고, 거기서 필요한 내용만 모아서 보는 방향으로 감.

이 논의 과정에서 프론트엔드 회의록에 "4. 백엔드 미팅 공유 사안" 섹션을 추가함 — 프론트팀이 백엔드가 알아야 할 내용을 여기 적어두면, 그 내용이 통합 회의록으로 옮겨지는 소스가 됨.

## 흐름

1. 매주 월요일 15:17 KST에 통합 회의 전용 GitHub Actions 크론이 실행됨 (프론트/백엔드 크론과 별개)
2. 그 주 월요일에 생성된 프론트엔드 회의록 페이지를 찾음
3. 그 페이지에서 "4. 백엔드 미팅 공유 사안" 섹션 내용만 파싱해서 추출
4. 같은 방식으로 백엔드 회의록의 "프론트 미팅 공유 사항" 섹션도 파싱해서 추출
5. 통합 회의록 페이지(신규 생성/갱신)에 양쪽 내용을 기입 — 프론트→백엔드, 백엔드→프론트 양방향 구조

**섹션 이름 매핑** (소스 문서 기준 이름 → 통합 회의록 기준 이름, 관점이 뒤집힘에 주의):

| 소스 | 소스 문서의 섹션명 | 통합 회의록의 섹션명 |
|---|---|---|
| 프론트 회의록 | "백엔드 미팅 공유 사안" (백엔드가 알아야 할 것) | "프론트 공유 사안" (프론트가 공유하는 것) |
| 백엔드 회의록 | "프론트 미팅 공유 사항" (프론트가 알아야 할 것) | "백엔드 공유 사안" (백엔드가 공유하는 것) |

## 통합 회의록 템플릿 구조

프론트 회의록과 동일한 스타일(번호 1.~5. + 참가자/작업 항목은 a./b./c. 들여쓰기)로 감.

```
날짜
   [실행일]

참가자 (팀별로 나눠서 표기)
   프론트엔드: 서지권, 이수현, 김준열
   백엔드: 유세정, 박상혁

1. 프론트 공유 사안
   (프론트 회의록의 "백엔드 미팅 공유 사안" 섹션에서 자동으로 가져와 채워짐)

2. 백엔드 공유 사안
   (백엔드 회의록의 "프론트 미팅 공유 사항" 섹션에서 자동으로 가져와 채워짐)

3. 최종 공유 사안
   ("전체 회의 공유 사안"에 해당하지 않는 것들을 기록 — 수동 작성)

4. 전체 회의 공유 사안
   (통합 회의 중 결정된 내용을 여기서 직접 작성 — 각 팀 회의록에는 더 이상 안 둠, 통합 회의록에서만 관리)

5. 공유/이슈/질문 공유
   (개발팀 내부 사항, 필요시 작성 — 프론트 회의록과 동일한 이름으로 통일)
```

페이지 제목 형식: `MM월 DD일 개발 미팅`

프론트 회의록의 "5. 전체 회의 공유 사안" 섹션은 통합 회의록으로 이관되면서 제거함 (`frontend/weekly_report.py` 반영 완료, 중복 관리 방지). 백엔드 회의록도 처음부터 이 섹션 없이 만듦.

## 확정된 값

| 항목 | 값 |
|---|---|
| 통합 회의 요일/시간 | 매주 월요일 15:17 KST (`17 6 * * 1` UTC — 정각 대신 정각 혼잡을 피해 17분으로 미룸) |
| 들어갈 스페이스/폴더 | `00-팀` 스페이스 > `개발 미팅` 폴더 > `통합 YY년 M월` 월별 폴더(자동 생성, 프론트와 동일 패턴) |
| 데이터 반영 방식 | 양방향 (프론트↔백엔드 각자 회의록에 상대 팀 공유 섹션을 두고, 통합 회의록이 양쪽을 모아 가져옴) |
