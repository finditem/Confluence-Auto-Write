# 백엔드 주간 회의록 자동화 (계획, 미착수)

> 상태: 설계 중 — 아직 코드 작업 시작 안 함. 아래 미정 사항 정리되면 착수.

## 왜 필요한가

지금 있는 `weekly_report.py`는 프론트엔드 팀 전용. 같은 방식으로 백엔드 팀 주간 회의록도 자동 생성하고 싶음.

## 확정된 것

- 전체 구조는 프론트엔드 자동화와 동일 (GitHub 커밋 로그 수집 → 사람×카테고리별 정리 → OpenAI 요약 → Confluence 페이지 upsert)
- 별도 크론으로 실행 (프론트 크론과 요일/시간 다름)
- 프론트 회의록에 "백엔드 미팅 공유 사안" 섹션이 있는 것과 대칭으로, 백엔드 회의록에도 **"프론트 미팅 공유 사항"** 섹션을 넣음 → 통합 회의록은 양쪽 회의록에서 각각 해당 섹션을 가져오는 양방향 구조가 됨 ([combined-report-plan.md](./combined-report-plan.md)의 "백엔드 쪽 데이터 반영 방식" 항목 참고)

## 아직 미정 — 착수 전 확인 필요

| 항목 | 상태 |
|---|---|
| 실행 요일/시간 (크론 값) | 미정 |
| 회의록 템플릿 구조 | 미정, 프론트 템플릿 그대로 쓸지 다르게 갈지 고민 필요 |
| 대상 인원 (`PEOPLE`, `PERSON_CATEGORIES`) | 미정 — 백엔드 팀원 명단, accountId 조회 필요 |
| 대상 저장소/경로별 카테고리 규칙 (`REPO_RULES`) | 미정 — 백엔드가 다루는 저장소 목록, 경로별 분류 기준 |
| 페이지 제목 형식 | 미정 — 프론트는 `MM월 DD일 미팅`, 백엔드도 동일할지 다르게 할지 |
| 들어갈 스페이스/폴더 | 미정 |

## 참고

- [combined-report-plan.md](./combined-report-plan.md) — 프론트+백엔드 통합 회의록 계획. 거기서 "백엔드 쪽 데이터"가 이 자동화에서 나오게 될 가능성이 있어서 연관됨. 이 계획이 정리되면 통합 회의록 계획의 "백엔드 쪽 데이터 반영 방식" 항목도 같이 풀릴 수 있음
- 참고 구현체는 `../weekly_report.py`
